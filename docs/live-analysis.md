# Live analysis workspace

Open `/analysis` in the Vite frontend, or choose **Run live B11 comparison** on the policy briefing. It uses real B11 jobs regardless of the map's fixture toggle. Run Express on port 8010 and Vite on 5173 for the default development proxy.

Enter housing counts, phase year, budgets and fleet allowance. Select the upgrade checkbox to inspect and explicitly submit the interface's cycle, headway and cost assumptions. Since the A10 integration, omitted policies use the server's reviewed 300-second policy, exposed at `/api/corridor/interventions`; zero budgets still reject upgrades. These are scenario assumptions and transferred cost ranges, not project quotes. The server validates ranges, budgets, sources, availability and the extra-service fleet constraint. The headless demo additionally supports two phases and 20 seeds; Lane D must decide how to expose those controls in its interface.

The client creates a scenario, applies a versioned patch, enqueues a B11 job, polls it, then loads its stored comparison, summary, native metrics and selected replay. Errors stay visible; live failures never silently substitute fixture numbers. Editing the form marks the displayed results as belonging to earlier inputs. Submitted scenarios remain immutable versions. Leaving the page stops browser polling, not server computation.

Live Comparison 3.0.0 decisions use B11's native metrics: stranded riders are separate from neutral cutoff riders, and denied share uses the encountered-car denominator. Legacy 2.0.0 fixtures remain readable. The replay reads `b11-events-v1`, including passenger-arrival queues and incoming vehicle occupancy. Vehicles interpolate between recorded movement events; a slider and playback controls scrub the selected run. The map can open the latest completed comparison in the current browser session.

For a hosted frontend, set `VITE_API_BASE_URL=https://urbanova-production-ec5f.up.railway.app/api` before building. Set Railway's `CORS_ORIGINS` to a JSON array containing the exact deployed frontend origin. Gemini and database credentials stay on the backend. `frontend/.env.example` documents public build variables and the existing map token.
