# Live analysis workspace

Open `/analysis` in the Vite frontend, or choose **Run live B11 comparison** on the policy briefing. It uses real B11 jobs regardless of the map's fixture toggle. Run Express on port 8010 and Vite on 5173 for the default development proxy.

Enter housing counts, phase year, budgets and fleet allowance. Existing service requires no upgrade policy. Select the upgrade checkbox to review baseline/lane cycle times, headways, service hours/days and low/central/high cost ranges. These starting values are illustrative. Confirm them as your own assumptions before submission; they are sent explicitly in the job, never activated as a hidden server default. The server validates ranges, budgets, sources, availability and the frozen extra-service fleet constraint. Only feasible tested packages are evaluated; rejected package reasons remain in the comparison warnings.

The client creates a scenario, applies a versioned patch, enqueues a B11 job, polls it, then loads its stored comparison, summary, native metrics and selected replay. Errors stay visible; live failures never silently substitute fixture numbers. Editing the form marks the displayed results as belonging to earlier inputs. Submitted scenarios remain immutable versions. Leaving the page stops browser polling, not server computation.

The comparison decision retains Comparison 2.0.0's conservative cutoff definition. The native B11 table explicitly separates stranded riders from neutral cutoff riders and labels its encountered-car denied-share denominator. The replay reads `b11-events-v1`, including passenger-arrival queues and incoming vehicle occupancy. Vehicles interpolate between recorded movement events; a slider and playback controls scrub the selected run. The map can open the latest completed comparison in the current browser session.

For a hosted frontend, set `VITE_API_BASE_URL=https://urbanova-production-ec5f.up.railway.app/api` before building. Set Railway's `CORS_ORIGINS` to a JSON array containing the exact deployed frontend origin. Gemini and database credentials stay on the backend. `frontend/.env.example` documents public build variables and the existing map token.

The public domain was checked on 2026-10-17: it served the old FastAPI foundation (`foundation-v1`), returned 404 for `/health` and `/api/scenarios/default`, and 503 for `/api/health/db`. The workspace has no Railway login/token. To migrate that service, set its Root Directory to `/`, use `/railway.json`, remove a legacy uvicorn start override and deploy the current main branch. Ensure `DATABASE_URL` is a variable available to this service. The committed root Railway config builds `server/Dockerfile`, starts Express and checks `/health`. Verify public `/health`, `/api/health/db` and `/api/scenarios/default` after redeployment; local success does not establish hosted readiness.

Upgrade costs in this probe were confirmed illustrative assumptions, not reviewed quotes.
